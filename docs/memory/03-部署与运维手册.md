### 实盘 API Key

1. Gate 后台创建 API Key：只读分析只需读取权限；要下单再开合约交易，关闭提现，IP 白名单
   填 `81.71.71.131`。
2. 打开面板 `#/live`，填 Key/Secret，保存（写入 `.env`），点“测试连接”。
3. 打开“启用实盘账户同步”后即可看到余额/持仓/挂单/成交/流水分析。
4. **下单默认锁定**：`GRIDTRADE_LIVE_TRADING=0`。需要下单时在页面勾选并确认，才会把总开关置 1；
   未解锁时所有写接口返回 403。

内存限制是为了保护机器上其他服务；cgroup 触发时只会杀掉本服务，不会拖垮整机。

## 3. 首次部署步骤（可重放）

```bash
# 本地
rsync -az --exclude '.venv' --exclude 'web/node_modules' --exclude 'node_modules' \
  --exclude 'apk' --exclude 'var' --exclude '.git' --exclude '__pycache__' --exclude '*.pyc' \
  ./ ubuntu@81.71.71.131:~/gridtrade/

# 服务器
ssh ubuntu@81.71.71.131
cd ~/gridtrade
python3 -m venv .venv
.venv/bin/python -m pip install -q --upgrade pip
.venv/bin/pip install -q .
```

然后写入上面的 systemd 单元：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gridtrade
systemctl is-active gridtrade
curl -s http://127.0.0.1:8000/api/health
```

## 4. 更新发布流程

当前服务器是普通 `pip install .`（非 editable），修改 Python 代码后必须重装：

```bash
# 本地构建前端
cd web && pnpm build && cd ..

# 同步（注意保护服务器上的 var/ 和 data/）
rsync -az --delete \
  --exclude '.venv' --exclude 'var' --exclude 'research/data' \
  --exclude 'node_modules' --exclude 'apk' --exclude '.git' \
  ./ ubuntu@81.71.71.131:~/gridtrade/

# 服务器
ssh ubuntu@81.71.71.131 'cd ~/gridtrade && .venv/bin/pip install -q . && sudo systemctl restart gridtrade'
```

只改前端时不需要重装依赖，rsync `web/dist` 后重启服务或让浏览器强制刷新即可（index.html 为 no-cache，资源带 hash）。

`--delete` 会删除服务器上未出现在本地的文件；已排除 `var/`、`research/data/`，但仍建议先 `rsync -n` 演练。**不要删除服务器上的 `var/gridtrade.db`**，那是任务历史。

建议后续把服务器改为 `pip install -e .`，这样 Python 代码更新只需重启，不必重装。

当前采用“直接开放 IP:8000（HTTP）”，已生效：

- 公网地址：**http://81.71.71.131:8000**
- 监听：`0.0.0.0:8000`；ufw 已放行 `8000/tcp`（v4 与 v6）；云安全组也已放行
- 令牌：服务器 `~/gridtrade/var/token`（具体值不写入仓库）
- 已验证：`/api/health` 200；正确令牌登录成功、错误令牌 401；公网 9 页；回放完成（−0.04%，14 图）；WebSocket 正常；APK 真机公网访问正常

**重点：这是明文 HTTP，令牌与页面内容可被中间人截获，仅建议临时使用。**

后续切换到 HTTPS（推荐）：

1. 域名解析到 `81.71.71.131`，放行 443（ufw + 云安全组）。
2. 用 nginx/Caddy 反代到 `127.0.0.1:8000`，并把服务的 `GRIDTRADE_HOST` 改回 `127.0.0.1`。
3. 设置 `GRIDTRADE_SECURE_COOKIE=1`，重启服务。
4. 验证 HTTPS 登录、WebSocket、10 页、回放与模拟盘后，删除 ufw 的 8000 规则。

临时安全访问（不改公网暴露面）：

```bash
ssh -L 18000:127.0.0.1:8000 wmac@81.71.71.131
# 浏览器访问 http://127.0.0.1:18000
# 令牌：ssh wmac@81.71.71.131 'sudo cat ~/../ubuntu/gridtrade/var/token'
```

### 管理后台

- 地址：`http://<host>:8000/admin`；默认账号 `admin` / 密码 `admin`。
- 密码以 PBKDF2 哈希存 `var/admin.db`；会话 Cookie 为 `gt_admin`（12h，SameSite=Strict）。
- 首次登录请修改密码；HTTP 下密码明文，公网使用必须尽快上 HTTPS。
- 后台可改 Gate 凭据/限额、模拟盘标的/参数、启停/重置、轮换面板令牌、查看审计。
- 轮换面板令牌后，浏览器与 APK 的旧令牌立即失效（APK 需重新打包 `.env`）。
- 备份：`var/admin.db` 与 `var/gridtrade.db`、`var/paper.db` 一起打包。

## 7. 已知环境问题

- **服务器无法访问 Binance（根因：DNS 污染 + SNI 阻断）**：
  - 服务器在腾讯云广州（`ap-guangzhou-3`），中国大陆出口。
  - DNS 被污染：`fapi.binance.com` 在系统 DNS / 223.5.5.5 / 119.29.29.29 / 8.8.8.8 分别返回
    `157.240.12.35`、`208.43.170.231`、`31.13.95.17`、`128.242.240.85` 等伪造 IP（真实为
    CloudFront `18.65.x`），IPv6 返回伪造的 `2001::...`。
  - 即使手动用真实 IP（`curl --resolve ...:18.65.14.84`）：TCP 443 能建立，但 TLS ClientHello
    带 `SNI=fapi.binance.com` 会被重置（`errno=104`）；换成非 Binance SNI 可握手。80 端口同样不通。
    即：**按域名/SNI 的出口阻断**，不是安全组或服务器防火墙。
  - 对照：`data-api.binance.vision`（现货数据镜像，SNI 未被封）可访问；GitHub 可访问；
    Google/OKX/Bybit 也超时。说明是选择性网络封锁，不是本机配置。
  - 影响：Binance 实时行情与实盘不可用；历史数据继续在本地抓取后上传。
  - 处理：服务器 `.env` 设 `GRIDTRADE_MARKET_LIVE=0`；`LiveMarket` 失败缓存 60s、连接 1.5s/总 3s 超时；
    静态资源 gzip。曾导致 `/api/overview` 20s，现 **0.09–0.14s**。
  - 要恢复 Binance：使用可信的海外代理/中转（httpx 默认读取 `HTTPS_PROXY`，可在 `.env` 配置），
    或把服务迁到香港/新加坡等可直连区域；仅用 `data-api.binance.vision` 只能取现货行情，没有
    合约与资金费。
- **APK 性能基线**（OnePlus PJA110 / Android 16）：页面 DOM 加载约 0.28s，总览请求 148ms，JS 595KB（gzip 177KB，缓存后 0 传输），PSS 约 116MB，掉帧 1.59%（50th 8ms / 90th 10ms / 99th 20ms）。瓶颈来自服务端 API，不是 WebView。
- **Gate 行情**：`api.gateio.ws` 可访问；默认四标的 `SKHY_USDT/SPCX_USDT/GOOGL_USDT/AMGN_USDT`，1 张 = 0.01 标的；AMGN 最小价格变动 0.1、24h 成交额很小（约 $1k），纸面成交会比真实盘口乐观；单一 `spacing_bp` 对 AMGN 需 ≥约 2.2bp。
- **模拟盘账户库**：`var/paper.db`；从单标的旧库升级时启动会自动重建，旧成交不保留。
- **接口合规**：外部接口清单见 `docs/memory/07-外部接口清单与官方文档对照.md`；新增接口必须同步文档与 `tests/test_external_endpoints.py` 白名单，否则测试失败。
- **Python 包安装**：pip 输出过 `_enforce_underscore` 警告，不影响安装与运行。
- **磁盘余量**：仅约 5.7GB，回测产物与日志增长需关注；产物目前很小（`var/` 约 64KB/次测试）。
- **单 worker**：uvicorn 单进程；回放任务在后台线程执行，长任务会占用 CPU。3.7GB 内存下不建议并发多个大回测。
- **无 HTTPS**：443 未放行，也没有证书；使用公网 HTTP 前必须补上。
