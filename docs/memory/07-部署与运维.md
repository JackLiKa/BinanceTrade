## 速读（TL;DR）

- 线上只有**一台**服务器：腾讯云广州 `81.71.71.131`，Ubuntu 24.04.4，公网入口 `http://81.71.71.131:8000`（**明文 HTTP，未上 HTTPS**）。〔B〕
- 服务是 systemd 单元 `gridtrade`，`WorkingDirectory=/home/ubuntu/gridtrade`，`EnvironmentFile=.env`，监听 `0.0.0.0:8000`，`Restart=on-failure`。〔B〕
- 部署方式是**手工 rsync + `pip install .`（非 editable）**，没有 CI/CD、没有 GitHub 自动部署。改 Python 代码必须重装，只改前端则 rsync `web/dist` 即可。
- **这台机器上有其他业务**（nginx、3000/3010/8090/8100 等端口），不要动别人的 nginx 站点、端口和 ufw 规则。服务自身有 cgroup 内存上限 `MemoryHigh=1200M / MemoryMax=1800M`，就是为了保护同机其他服务。〔B〕
- **最大风险**：明文 HTTP + 单令牌全权限 + 后台默认密码 `admin/admin`。上 HTTPS 是 P0（见 [12 待办](12-待办与路线图.md)）。
- 服务器出口**访问不到 `fapi.binance.com`**（DNS 污染 + SNI 阻断），所以 `.env` 里 `GRIDTRADE_MARKET_LIVE=0`，面板行情回退本地数据集；模拟盘用 Gate 行情不受影响。（根因见 §7.1）
- 三个 SQLite（`var/gridtrade.db`、`var/paper.db`、`var/admin.db`）与 `var/token` 是**不可再生数据**，备份就是打包 `var/`。

〔B〕服务器上的实际布局：

```
/home/ubuntu/gridtrade/
├── .venv/                     Python 依赖（pip install . 非 editable）
├── .env                       全部 GRIDTRADE_* 配置（0600，不入库）
├── src/  web/  research/  tests/  docs/    代码（rsync 自开发机）
```

关键点：

- **`WorkingDirectory` 就是部署根**，`config.py` 的 `.env` 路径解析会优先用 `cwd`（见 [04 §1.1](04-配置与数据存储.md#11-env-文件解析顺序)）。
- 因为是非 editable 安装，`REPO_ROOT` 会指向 `.venv` 内，**不要依赖包内路径**；页面把配置写回 `.env` 时靠的是 `cwd` 或 `GRIDTRADE_ENV_FILE`。
- 数据与产物都在部署根，**rsync 时必须排除**。

## 3. systemd 单元

〔B〕录原样（`/etc/systemd/system/gridtrade.service`）：

```ini
[Unit]
Description=gridtrade research panel
After=network.target

[Service]
Type=simple
User=ubuntu
Group=ubuntu
WorkingDirectory=/home/ubuntu/gridtrade
Environment=PYTHONUNBUFFERED=1
EnvironmentFile=/home/ubuntu/gridtrade/.env
MemoryHigh=1200M
MemoryMax=1800M
ExecStart=/home/ubuntu/gridtrade/.venv/bin/python -m gridtrade.api
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

说明：

- `EnvironmentFile` 只在**启动时**读一次 → 改 `.env` 必须 `systemctl restart gridtrade`。
- 真实环境变量优先于 `.env`（`config.py` 用 `os.environ.setdefault`），所以既能被 systemd 覆盖，也能被 `EnvironmentFile` 补全。
- 内存上限是硬约束：并发大回测会先被 cgroup 限制而不是拖垮整机。**串行跑回测**。

## 6. 更新发布流程

〔B〕当前服务器是**非 editable** 安装，改了 Python 代码必须重装：

```bash
# 1) 开发机：构建前端 + 同步（注意保护服务器 var/、research/data/）
cd <repo>
pnpm --dir web build
rsync -az --delete \
  --exclude '.venv' --exclude 'var' --exclude 'research/data' \
  --exclude 'node_modules' --exclude 'apk' --exclude '.git' \
  ./ wmac@81.71.71.131:~/gridtrade/

# 2) 服务器：重装 + 重启
cd ~/gridtrade && .venv/bin/pip install -q . && sudo systemctl restart gridtrade
```

注意事项：

- **`--delete` 会删除服务器上本地没有的文件**。已排除 `var/`、`research/data/`，但仍建议先 `rsync -n`（dry-run）演练一遍。
- **绝对不要删除 `var/gridtrade.db`**（任务历史）、`var/paper.db`（模拟盘账户）、`var/admin.db`（后台账号）。
- 只改前端时：rsync `web/dist` 后重启服务即可；浏览器/APK 需强刷（`index.html` 为 no-cache，静态资源带 hash，正常刷新即可）。
- 建议把服务器改成 `pip install -e .`，这样改 Python 只需 `systemctl restart`（见 [12 待办](12-待办与路线图.md)）。

**三处"标的"互相独立，容易搞混**：

| 场景 | 来源 | 怎么改 |
| --- | --- | --- |
| 研究/回测页面的交易对 | `research/data/*_1m.parquet` | 上传数据集 + 重启 |

### 10.2 恢复 Binance 实时行情（代理方案）

代码支持 `GRIDTRADE_PROXY`（HTTP CONNECT 或 SOCKS5；SOCKS5 需要 `socksio`）。代理必须是**端到端 TLS（CONNECT 隧道）**，不能做 HTTPS MITM，否则证书校验失败。

```bash
# 1) 先验证代理能到 fapi
curl -s -x http://127.0.0.1:1080 -m 8 https://fapi.binance.com/fapi/v1/ping
curl -s -x socks5h://127.0.0.1:1080 -m 8 https://fapi.binance.com/fapi/v1/ping

# 2) 写入 .env
GRIDTRADE_PROXY=http://127.0.0.1:1080
GRIDTRADE_MARKET_LIVE=1

# 3) 重启并验证 source
sudo systemctl restart gridtrade
curl -s -H "Authorization: Bearer $(sudo cat ~/gridtrade/var/token)" \
  http://127.0.0.1:8000/api/market/snapshot \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['source'])"
# 期望 source=binance；失败会回退 dataset 并带 error 字段
```

- 已验证（历史，本地环境）：起一个 CONNECT 代理后设 `GRIDTRADE_PROXY=http://127.0.0.1:8899`，`/api/market/snapshot` 返回 `source=binance`。
- **合规警告**：Binance《Prohibited Use Policy》禁止通过匿名代理访问其服务。**代理只适合拉公开行情，不要用它驱动 Binance 账户/实盘**。做 Binance 实盘请按 [12 待办](12-待办与路线图.md) 的 Plan B（海外执行节点）走。
- 推荐实现：香港/新加坡小 VPS 上 `gost`/`tinyproxy`/WireGuard，仅允许本服务器 IP；或 `ssh -D 1080` 动态转发并用 systemd 保持隧道。**不要用公共免费代理或第三方 Binance 镜像**。

### 10.3 管理后台 `/admin`

- 地址 `http://<host>:8000/admin`；默认账号 `admin` / 密码 `admin`（**必须改**）。
- 密码以 PBKDF2-HMAC-SHA256（200k 轮 + 随机盐）存 `var/admin.db`；会话 Cookie `gt_admin`（httpOnly，SameSite=Strict，12h）；登录失败 5 次锁 30 秒。
- 功能：概览（模拟盘/实盘状态、令牌后四位、审计）、Gate 凭据与限额、模拟盘标的与参数、启停/重置、轮换面板令牌、改密码、审计日志；配置写服务器 `.env`。
- **轮换面板令牌后**：浏览器旧 Cookie/localStorage 立即失效需重新登录；**APK 因令牌编译进包，必须重新构建才能用**。
- 备份时把 `var/admin.db` 与另外两库一起打包。

### 10.5 实盘（Gate）配置

1. Gate 后台创建 API Key：只读分析只需读取权限；要下单再开合约交易，**关闭提现**，IP 白名单填 `81.71.71.131`。
2. 打开 `#/live` 填 Key/Secret 保存（写回 `.env` 0600），点"测试连接"。
3. 打开"启用实盘账户同步"后即可看余额/持仓/挂单/成交/流水分析。
4. **下单默认锁定**：`GRIDTRADE_LIVE_TRADING=0`；需要下单时在页面勾选并确认才置 1。锁定时下单/撤单/平仓会被拒：未启用实盘或未配置 Key 返回 **409**，已启用但未解锁返回 **403**；`POST /api/live/config`（保存配置）不受此锁约束。

- **DNS 污染**：`fapi.binance.com` 在系统 DNS / 223.5.5.5 / 119.29.29.29 / 8.8.8.8 分别解析出 `157.240.12.35`、`208.43.170.231`、`31.13.95.17`、`128.242.240.85` 等伪造 IP（真实为 CloudFront `18.65.x`），IPv6 返回伪造 `2001::...`。
- **SNI 阻断**：即使用 `curl --resolve` 指定真实 IP，TCP 443 能建立，但 TLS ClientHello 带 `SNI=fapi.binance.com` 会被重置（`errno=104`）；换非 Binance SNI 可握手。80 端口同样不通 → **按域名/SNI 的出口阻断**，不是安全组或本机防火墙。
- 对照：`data-api.binance.vision`（现货数据镜像）可访问；GitHub 可访问；Google/OKX/Bybit 也超时 → 选择性封锁。
- **香港 IP 实测**：用 check-host 香港节点（`141.98.234.68`，AS207713）请求 `fapi.binance.com` 的 `/fapi/v1/ping`、`/premiumIndex`、`/klines` 均返回 **200**（CloudFront 边缘，约 65–100 ms）→ 香港 IP 可解决**行情访问**，但不改变**账户产品资格**：Binance 2021 公告限制香港用户的衍生品账户（不可开新合约、存量 90 天内平仓）。若要做 Binance 实盘，先确认账户地区与合规资格。
- **测试网**：广州服务器可直连 `testnet.binancefuture.com`（200，约 1.4 s），可用于零成本验证下单/撤单/对账逻辑。

### 11.2 其它环境约束
