# 18 Binance 式爆仓引擎（回测 + 模拟盘）

> **用途**：记录 gt 项目（gridtrade）新增的 USDⓈ-M 维持保证金/强平引擎，解释公式、触发条件、费用与边界。
> **最后核实**：2026-11-18 · 代码基线 `main` · pytest 174 项

## 1. 为什么加

旧回测只有线性现金账户，没有保证金/强平：
- 权益可以变成负数，之后继续交易并“涨回来”；
- 最大回撤出现 `-134%` 这类数学上不可能的数字；
- 结果不能用于实盘参数选择。

现在回测和实时模拟盘共用 `src/gridtrade/risk/liquidation.py`，实盘仍是只读。

## 2. Binance 规则映射

### 2.1 维持保证金
```
maintenance_margin = notional * MMR - maintenance_amount
```
- **API 回测优先使用真实 Binance `/fapi/v1/leverageBracket`**：
  - 东京节点 `/market/leverage-bracket` 返回当前 symbol 的档位；
  - GOOGLUSDT 实测：≤50,000 名义 MMR=1.0%，cum=0；后续档位按 Binance 返回；
  - 同时从 `/market/contract` 取 `liquidationFee`（GOOGLUSDT 实测 1.5%）。
- 无节点/离线时才回退到内置保守表（与 Binance 低名义档形似，但非实时）；
- 回测 artifact 的 `meta.params.maintenance_tiers/liquidation_fee` 会记录本次实际使用的档位和强平费。

### 2.2 保证金余额
```
wallet_balance = cash + position * entry_price
margin_balance = wallet_balance + unrealized_pnl
margin_ratio   = maintenance_margin / margin_balance
```
- 全仓/逐仓在单 symbol 下公式相同：全仓等于把 cross wallet 当作 wallet balance。

### 2.3 强平价
```
long:  LP = (qty*entry - wallet - maintenance_amount) / (qty*(1 - MMR))
short: LP = (wallet + qty*entry + maintenance_amount) / (qty*(1 + MMR))
```
- 档位会随 notional 变化，迭代到稳定。
- 例：1 张、entry 100、wallet 10、MMR 1%（GOOGLUSDT 第一档）：
  - 多单 LP ≈ 90.91
  - 空单 LP ≈ 108.91

### 2.4 触发
- 多单：bar.open <= LP（跳空用更差的 open）、bar.low <= LP、或 bar.close <= LP；
- 空单：bar.open >= LP、bar.high >= LP、或 bar.close >= LP；
- 另加保护：`margin_balance <= maintenance_margin` 直接强平（慢跌也能抓到）。
- 强平后：
  - 撤销全部挂单；
  - 按强平价（跳空按 open）平掉全部仓位；
  - 收取真实 `liquidationFee`（本次 GOOGLUSDT 为 1.5%；离线回退 0.5%）；
  - 正常强平（按强平价成交）权益不为负；
  - **跳空穿仓/强平失败**允许负权益，负的部分记为 `bad_debt`，不静默截成 0；
  - `liquidated=True`，引擎停止，不再接受新订单；
  - **账户权益回撤不再强行封顶 100%**：负权益时最大回撤可以超过 100%，这是坏账，不是可恢复收益。

## 4. 结果与验证

- 新增测试：`tests/test_liquidation.py`、`test_engine.py` 爆仓用例、`test_paper.py` 组合强平用例；
- 回测崩溃路径测试：强平后 `liquidated=true`、期末持仓 0；有跳空时允许 `bad_debt>0` 和账户权益回撤超过 100%；
- 模拟盘：权益 ≤ 维持保证金时全部平仓、权益清零、状态 halted；
- pytest **175 项**通过。

## 5. 边界（尚未覆盖）

- 用 1m bar 的 open/high/low/close 近似 mark price；没有逐笔/盘口冲击。
- 未实现 Binance 保险基金、ADL、强平清算费阶梯、逐仓多空双向持仓、跨 symbol 精细强平价。
- API 回测已自动拉真实 leverage bracket；CLI/离线仍可用内置回退表。
- **指标口径**：最大回撤/总收益按**账户权益**计算；仓位或占用保证金的收益率可以低于 -100%，这属于另一个指标，不能与账户回撤混用。
- 实盘（Gate/Binance 账户）仍是只读；引擎只负责回测和模拟盘的风险真实性。


## 6. 官方文档核对

  - 字段：`bracket` / `initialLeverage` / `notionalCap` / `notionalFloor` / `maintMarginRatio` / `cum`
- [Exchange Information](https://developers.binance.com/legacy-docs/derivatives/usds-margined-futures/market-data/rest-api/Exchange-Information)
  - 字段：`liquidationFee`
- [How to Calculate Liquidation Price of USDⓈ-M Futures Contracts](https://www.binance.com/en/support/faq/detail/b3c689c1f50a44cabb3a84e663b81d93)
  - 多/空、全仓/逐仓强平价公式

代码中的实现与上述字段/公式一一对应；真实档位由东京节点 `GET /fapi/v1/leverageBracket` 拉取，强平费由 `GET /fapi/v1/exchangeInfo` 的 `liquidationFee` 提供。
