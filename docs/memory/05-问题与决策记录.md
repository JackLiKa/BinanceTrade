# 05 问题与决策记录

## 1. 本次修复的真实缺陷

### 1.1 APK 原生界面为英文

- 现象：首次启动设置页、连接错误页、原生菜单、退出登录确认均为英文，而 WebView 内已是中文，体验割裂。
- 修复：`apk/src/com/gridtrade/panel/MainActivity.java` 中所有用户可见字符串改为简体中文（“量化研究终端”“服务器地址”“访问令牌”“打开面板”“无法连接服务器”“重试”“服务器与令牌”“重新加载”“退出登录”“清除本设备保存的令牌与 Cookie？”等）。
- 验证：卸载重装后 `uiautomator dump` 确认中文；错误页通过把服务器改为 `http://127.0.0.1:9` 触发（`net::ERR_UNSAFE_PORT`）；设置页、菜单、退出登录流程均实测。

### 1.2 主题 NoActionBar 导致原生菜单不可达

- 现象：`onCreateOptionsMenu` 添加的“重新加载/服务器与令牌/退出登录”没有任何入口，用户无法重新配置服务器或登出。
- 修复：删除 ActionBar 菜单回调；改为 `onBackPressed()`（`MainActivity.java:401`）：WebView 有历史则 `goBack()`，否则 `showPanelMenu()`（`:413`）弹出原生菜单（重新加载/服务器与令牌/退出登录/退出应用）。
- 验证：真机连续按返回键，页面内正常后退，历史尽头弹出中文菜单；菜单四项逐一验证。
- **注意**：WebView 中通过 CDP 直接改 `location.hash` 不会进入原生历史，因此“CDP 注入后按返回直接退出”不是缺陷；真实点击导航后行为正确。

### 1.3 切换历史任务触发 artifact 409

- 现象：点击历史里“已取消”或其他状态的任务时，`/api/runs/<id>/artifact` 返回 409（后端只允许 `succeeded`）。
- 根因：`selectRun` 先更新 `runId`，但 `useRunWatch` 里的 `run` 仍是上一个任务的“succeeded”；`useArtifact` 用旧状态判断可用，导致对新 runId 发起请求。
- 修复：`web/src/hooks.ts:103` 改为 `useArtifact(runId, run)`，仅当 `run.id === runId && run.status === 'succeeded'` 时才请求；四个调用点（Backtest/Overview/Orders/Positions）同步调整。
- 验证：先点成功任务再点已取消任务，网络面板无 409，成功任务结果仍正常渲染。

### 1.4 选中“已取消/排队中”任务仍显示上一份产物

- 现象：切到非成功任务时，页面仍显示上一个任务的权益图、月表与数值（属于别的 run），信息误导。
- 修复：`useArtifact` 在未就绪时返回 `data: null`，画面清空。
- 验证：成功任务 14 个 canvas → 切到已取消任务后 0 个，无残留。

## 2. 已知限制与未修问题

| 项 | 说明 | 建议 |
| --- | --- | --- |
| APK 默认服务器 `10.0.2.2` | 仅模拟器可用；真机必须手填，或 `adb reverse` 后用 `127.0.0.1` | 部署地址确定后改写 `DEFAULT_SERVER` 并重建，见 06 |
| `adb reverse` 不持久 | USB 重连/重启后失效 | 测试前重做，或在 APK 里改连局域网地址 |
| OPPO/OnePlus 安装器卡住 | `adb install` 停在安装引导 | 使用 `pm install-create/write/commit` |
| WebView 不暴露 UIAutomator 节点 | `uiautomator dump` 内容为空 | 用 `webview_devtools_remote` + CDP |
| 服务器无法访问 Binance | 实时行情超时，回退数据集，价格滞后（本地曾测到约 123 分钟延迟） | 换出口/代理，或接受历史数据模式 |
| 公开 HTTP 暴露 | 目前仅 loopback；用户尚未选择访问方式 | 优先域名 + HTTPS；令牌是单因子全权限 |
| WebView 调试已开启 | `MainActivity.java:252` 无条件开启，release 包也可调试 | 分发前改为仅 debug 构建开启 |
| 签名密钥未入库 | `apk/gridtrade.jks` 被忽略；`build.sh` 中口令硬编码（`gridtrade`） | 换机后重新生成密钥会导致旧包无法覆盖安装；如需长期分发，应安全保存 keystore |
| 无 CI/CD | 服务器代码为 rsync 手工部署，未接 GitHub | 可加 GitHub Actions 构建 web/dist 与 pytest |
| 单 worker + 内存上限 | 大回测并发可能触发 cgroup 限流/OOM | 串行执行，关注 `MemoryCurrent` |
| 测试脚本未入库 | `/tmp/gtweb/*.mjs` 为临时脚本 | 建议整理进 `tests/e2e/` |

## 3. 策略研究结论（重要，避免重复踩坑）

GOOGLUSDT USDⓈ-M 永续，1m 数据（2026-03-26..2026-11-16，235 天，337,778 根，718 次资金费结算）。

两个已修复的模型 bug：

1. **成交价 bug**：旧模型按 `target = -floor((P-anchor)/step)` 逐边界调仓，向下跨越时把回补价记低一整格，价格在边界抖动一次就白赚一个 step。1m 噪声下约 46 次/天、10,918 笔/235 天；合成随机游走 +90.5%±6.9%/60 天。改为状态机（相邻格各一单，high/low 必须真正触达，上涨 bar 只卖、下跌 bar 只买）后，随机游走回到 +1.45%±1.31%/60 天。
2. **资金费符号 bug**：旧脚本用 `abs(pos) * price * rate`，把资金费永远当成本。正确为 `cash -= pos * price * rate`；修复后旧 `Config(120,30,0.5, stop_dd=9.9)` 由 +3.33% 变为 +8.73%，与新引擎 +8.62% 交叉验证（差异 0.11pp，来自止损成交时点/mark 取价）。

修正后的真实结果：

- 静态全程锚点 120bp/30 格/0.5x，10% 止损：累计 **+8.62%**（年化 +13.74%），最大回撤 9.75%，646 笔，手续费 $27.9，资金费净收 $256，未触发止损。
- **但这是刀锋结果**：同配置止损 2%/3%/5% 分别为 -1.94%/-2.93%/-5.36%，全部止损；只有 10% 这一档活下来。收益符号由止损阈值决定，不是 edge。
- 月度再定锚 + 10% 止损：120bp/30/0.5x 累计 **-6.07%**；60bp/20/1x 累计 -5.48%。7/14/30 天再定锚全部为负；乐观 intrabar 仍为负。
- 合成零漂移 GBM 对照（新引擎）：-1.12%~+0.19%，均值约 -0.4%，无造钱迹象。

**结论：GOOGLUSDT 上不存在可部署的分钟级网格正期望。** 静态 +8.62% 本质是“4 月上涨中一路做空、回撤未触发 10% 止损、随后回落回补”的方向性库存押注，资金费净收只让持仓多活了约 25bp。基础设施可以保留，策略应转向有信息优势的方向（跨市场 lead-lag、事件驱动、带对冲的基差/资金费 carry），网格只适合小资金纸面验证。

## 4. 关键设计决策

| 决策 | 理由 |
| --- | --- |
| 纯 hash 路由 | 无服务端 rewrite 依赖，APK/静态托管简单；代价是无浏览器历史 API 的语义（已由 APK 返回键兜底） |
| 后端默认 `127.0.0.1` | 安全默认；公网必须显式改绑或反代 |
| 令牌单因子 + localStorage | 单用户场景简单；APK 另有 SharedPreferences 与原生设置页 |
| 任务队列用线程 + SQLite | 无额外基础设施；单机单用户足够；代价是不能横向扩展 |
| 前端构建产物由后端托管 | 一个进程、一个端口，APK 无需额外配置 |
| 数据源回退 | 实时接口不可用时使用数据集，保证面板可演示；但会误导“实时性”，需看数据源 pill |
| 仅研究/模拟，实盘锁定 | 产品边界；勿在未做订单对账、listenKey 续期前开放 |
| 服务内存 cgroup 限制 | 与服务器上其他业务共存，牺牲单任务上限换整机稳定 |
