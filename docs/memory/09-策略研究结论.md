## 速读（TL;DR）

- 结论一句话：**GOOGLUSDT 分钟级网格不存在可部署的正期望**。基础设施（引擎/回测/模拟盘）可以留，策略方向必须换。
- 唯一"好看"的数字：静态全程锚点 120bp/30 格/0.5x + 10% 止损 = **+8.62%（年化 +13.74%）**，最大回撤 9.75%。
- **但这个数字是刀锋结果**：同配置把止损改成 2%/3%/5% 立刻变成 -1.94% / -2.93% / -5.36%，全部止损离场。收益符号由**止损阈值**决定，不是 edge。
- 月度再定锚全部为负：120bp/30/0.5x 为 **-6.07%**，60bp/20/1x 为 **-5.48%**；7/14/30 天再定锚同样为负；乐观 intrabar 口径仍为负。
- 零漂移合成 GBM 对照：新引擎 **-1.12% ~ +0.19%（均值约 -0.4%）**——引擎不再"造钱"。
- 修正过两个真实 bug：**成交价 bug**（旧模型虚增，合成随机游走 +90.5%±6.9%/60 天）与**资金费符号 bug**（`abs(pos)` → `pos`，旧配置 +3.33% → +8.73%）。这两处是本项目最重要的建模修复。
- 成本结构：**库存/单边趋势 >> 手续费 > 资金费**。资金费净收 $256（本金的 2.6%）只让持仓多活约 25bp，救不了方向性库存。
- 四标的组合（SKHY/SPCX/GOOGL/AMGN）**只跑通了纸面运行，完全没有验证过期望值**。不要把"模拟盘在跑"当成"策略有效"。
- 下一步该做的方向：跨市场 lead-lag、事件驱动、带对冲的基差/资金费 carry；网格只保留小资金纸面验证。

## 2. 两个必须知道的建模 bug

### 2.1 成交价 bug（旧模型虚增收益）

**旧做法**：按 `target = -floor((P - anchor) / step)` 直接算目标仓位，逐边界调仓。

**错在哪**：价格向下跨越边界时，把"回补价"记低了**一整格**。价格只要在边界附近抖动一次，就白赚一个 `step`。

**规模**：1m 噪声下约 **46 次/天**、累计 **10,918 笔/235 天**。

**证据**：零漂移合成随机游走（本应期望≈0）上，旧模型跑出 **+90.5% ± 6.9% / 60 天**。

**修复**：改成**状态机撮合**——相邻格各挂一单，必须由 bar 的 high/low **真正触达挂单价**才成交；上涨 bar 只卖、下跌 bar 只买。

**修复后**：同一零漂移随机游走回到 **+1.45% ± 1.31% / 60 天**（约等于噪声）。120bp 配置下成交 467 笔。

> 代码位置：撮合逻辑在 `src/gridtrade/execution/`，回测引擎在 `src/gridtrade/research/engine.py`（详见 [02 后端架构](02-后端架构与领域模型.md)）。

### 2.2 资金费符号 bug（把收入算成成本）

**旧做法**：`cash -= abs(pos) * price * rate` → 无论多空，资金费**永远是成本**。

**正确**：`cash -= pos * price * rate`，即
- 正费率、多头（`pos > 0`）→ 现金减少（付费）；
- 正费率、空头（`pos < 0`）→ 现金增加（收费）。

**证据**：旧配置 `Config(120, 30, 0.5, stop_dd=9.9)` 由 **+3.33%** 变为 **+8.73%**；新引擎同配置 **+8.62%**，差 **0.11 pp**（来自止损成交时点与 mark 取价），互为交叉验证。新旧引擎的**成交笔数与手续费完全一致**，差异只在资金费——证明定位准确。

> 代码位置：`src/gridtrade/execution/simulated.py`、`src/gridtrade/research/engine.py`。

## 4. 为什么这是"刀锋"而不是 edge

同配置**只改止损阈值**，收益立刻翻转：

| 止损 | 累计收益 | 结果 |
| --- | --- | --- |
| 2% | **-1.94%** | 止损离场 |
| 3% | **-2.93%** | 止损离场 |
| 5% | **-5.36%** | 止损离场 |
| **10%** | **+8.62%** | 未触发止损 |

只有 10% 这一档"活下来"。含义：

- 收益来源不是网格的波动收割，而是——锚点 288，4 月标的上涨约 **+33%** 时网格一路做空，形成**空头库存**；回撤 9.75% 恰好没打到 10% 止损线；之后价格回落到 295 时库存回补，账面转正。
- 这本质是**一次方向性库存押注**，靠"止损线刚好差 0.25pp 没被打掉"存活。换个止损线或换个起点，符号就翻转。
- 资金费净收 $256（本金的 **2.6%**）只是让这笔库存多活了约 **25bp**，不构成 edge。

> 判据：如果一个策略的收益符号由**风控阈值**而不是**信号**决定，它就不是策略，是仓位巧合。

## 5. 月度再定锚与其它参数的结果

### 5.1 月度再定锚（更接近"可持续"的做法）

| 配置 | 累计收益 | 备注 |
| --- | --- | --- |
| 120bp / 30 格 / 0.5x + 10% 止损 | **-6.07%** | 月均 -0.67%，中位 +0.28%，最差 2026-04 **-6.62%**，正收益月 **6/9**，未触发止损 |
| 60bp / 20 格 / 1x + 10% 止损 | **-5.48%** | 4 月 -9.79%、10 月 -8.93%，触发 2 次止损 |

### 5.2 其它口径

| 变体 | 结果 |
| --- | --- |
| 7 / 14 / 30 天再定锚 | **全为负** |
| 乐观 intrabar 口径（成交假设更宽松） | 仍为负：60bp 约 **-5.2%/年**，120bp 约 **-13.6%/年** |
| 止损收紧到 2% 后扫 60+ 组参数 | 最好年化 +0.16%~+1.75%，属噪声，不可用 |

> **注意方向**：intrabar 乐观口径是"给策略最好的假设"；连乐观口径都是负的，说明问题不在成交悲观，而在信号本身没有 edge。

## 6. 合成数据对照（引擎自检）

用零漂移 GBM（几何布朗运动，无方向性收益）生成 5 条 20 天路径，用新引擎回测：

| 结果 | 含义 |
| --- | --- |
| **-1.12% ~ +0.19%**，均值约 **-0.4%** | 期望接近 0（略负=手续费/资金费），**引擎不再造钱** |

这是**验证引擎正确性的黄金测试**：任何新撮合模型、新参数化，都应该先在这个测试上通过（接近 0 或略负），再去跑真实数据。如果不通过，赚的钱是 bug 不是 alpha。

## 7. 成本结构拆解

GOOGLUSDT 期间：

| 成本/收入项 | 量级 | 说明 |
| --- | --- | --- |
| **库存/单边趋势风险** | 主导项 | 单边上涨期一路做空，浮亏决定生死；这是最大成本 |
| 手续费 | 次之 | 40~180 笔/月 → **$3~$30/月**；往返费率约 4bp（合约 maker） |
| 资金费 | 最小 | 费率均值 **+0.009367%/8h**（年化约 **10.26%**），中位 **0**；月度 **-$40 ~ +$56** |

**排序：库存/趋势 >> 手续费 > 资金费。** 这一条对策略设计的含义：

- 优化手续费/资金费是"捡芝麻"；**控制单边库存暴露才是主要变量**。
- 网格在震荡市赚的钱，会被趋势市的库存亏损一次性吃掉；这正是 §4 中"方向性押注"的本质。
- 若要继续网格路线，必须解决"趋势期库存上限/对冲"，而不是调 `spacing_bp`。

## 8. 结论与建议

### 8.1 结论（可直接引用）

> **在 GOOGLUSDT 的 235 天 1m 数据上，分钟级网格不存在可部署的正期望。** 唯一的正收益（+8.62%）来自"止损阈值恰好没被打掉的方向性空头库存"，不具稳健性；任何形式的再定锚（7/14/30 天、月度）或更紧止损都转为负收益。基础设施（引擎、回测、模拟盘、面板）可以保留，策略逻辑需要换方向。

### 8.2 建议

| 优先级 | 动作 |
| --- | --- |
| 1 | **不要**继续在 GOOGLUSDT（或类似高流动性美股永续）上找分钟级网格 edge，参数扫描已经做过 60+ 组 |
| 2 | 转向有信息优势的方向：**跨市场 lead-lag**（例如现货/期货、相关标的先后）、**事件驱动**、**带对冲的基差/资金费 carry** |
| 3 | 网格只保留为**小资金纸面验证**用途（现在的 `#/paper` 正好是这个定位） |
| 4 | 任何新策略上线前，必须先过 §6 的合成数据自检（期望≈0 或略负），再跑真实数据 |

## 9. 模型边界（别过度解读）

| 边界 | 影响 |
| --- | --- |
| 只有 1m bar | 无法还原盘中路径；保守口径**低估**成交与风险，乐观口径高估 |
| 单边极值假设 | 一个 bar 内只用一个 high/low，无法区分路径顺序 |
| 只有 9 个月样本 | 不足以估稳健 Sharpe；2026-04 一个月的行情主导了结论方向 |
| 资金费近似 | 差异 **< 0.05 pp**（与精确结算对比），可忽略 |
| 无盘口/滑点建模 | 真实成交会更差；本文的负数结论只会更差不会更好 |
| 单一标的 | 不能推广到"所有标的都不行"；但同一套参数化方式也没给出过正期望 |

## 10. 如何自己复核

CLI（`src/gridtrade/research/cli.py`，`pyproject.toml` 注册为 `gridtrade` 命令）：

```bash
# 0) 先确认数据在（不在就 fetch）
python research/fetch.py --symbol GOOGLUSDT

# 1) 数据质量
python -m gridtrade.research.cli dataset --symbol GOOGLUSDT

# 2) 单次回放（等价于面板的 replay 任务）
python -m gridtrade.research.cli replay \
  --symbol GOOGLUSDT --spacing-bp 120 --levels 30 --leverage 0.5 \
  --stop-dd 10 --equity-out /tmp/equity.csv

# 3) 月度再定锚（前向滚动）
python -m gridtrade.research.cli walkforward \
  --symbol GOOGLUSDT --spacing-bp 120 --levels 30 --leverage 0.5 --stop-dd 10

# 4) 参数扫描（间距/层数/杠杆）
python -m gridtrade.research.cli sweep \
  --symbol GOOGLUSDT --spacing-bp 60 --levels 20 --leverage 1 --stop-dd 10

# 5) 乐观口径：加 --intrabar；滑点：--slip-bp
```

常用参数（`--help` 实测）：`--symbol --start --end --capital --spacing-bp --levels --leverage --reanchor-bars --stop-dd --maker-fee --taker-fee --slip-bp --intrabar --equity-out`；`walkforward` 另有 `--min-days`。

**复核时务必确认**：资金费方向用 `cash -= pos * price * rate`（不是 `abs(pos)`），成交必须由 high/low 触达挂单价（不是按边界直接调仓）。否则你会重现 §2 的两个 bug，得到虚高的正收益。

## 11. 四标的组合：未验证

模拟盘默认组合是 `SKHY_USDT / SPCX_USDT / GOOGL_USDT / AMGN_USDT`（共享保证金、单标的独立网格）。当前状态：

| 项 | 状态 |
| --- | --- |
| 是否跑通 | ✅ 真实 Gate 行情下有成交、手续费、资金费、权益落库 |
| 期望值 | ❌ **从未验证**（没有做组合级 replay/sweep，也没有回测结论） |
| 参数风险 | 4 标的共用一个 `spacing_bp`：AMGN 的 tick 是 0.1，间距需 ≥约 2.2bp；低价标的又被拉宽 |
| 流动性风险 | AMGN 24h 成交额仅约 **$1k**，纸面按挂单价成交会明显乐观 |
| 结论 | 它是**纸面观察工具**，不是"已验证可盈利的组合" |

要做组合级验证，至少需要：4 个标的的历史数据、组合级回放（共享保证金 + 逐标的资金费）、以及参数按标的覆盖的能力（见 [12 待办](12-待办与路线图.md)）。
