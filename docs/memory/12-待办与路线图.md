## 速读（TL;DR）

- **没有阻塞开发的代码缺陷**。所有"能跑起来"的部分都跑通了，剩下的都是加固、扩展与决策。
- **P0 只有三件**：① 上 HTTPS（需要域名）；② 改掉后台默认密码 `admin/admin`；③ 决定 Binance 实盘走不走"海外执行节点"方案。
- **最大的认知风险**不是技术债，而是**把模拟盘在跑当成策略有效**。四标的组合从未验证期望值（[09 §11](09-策略研究结论.md#11-四标的组合未验证)）。做任何实盘前必须先补组合级回测。
- **P1 是模拟盘增强**：金融级真实度（WebSocket 行情、每标的参数、精确资金费、盘口/滑点）。
- **P2 是工程化**：端到端脚本入库、CI、Windows 测试兼容、前端单测。
- **P3 是运维加固**：定时备份、日志轮转、监控、`pip install -e .`。
- **P4 是策略方向**：停止在分钟级网格上找 edge，转向 lead-lag / 事件驱动 / 带对冲的 carry。
- 本机（Windows）已确认的两个小尾巴：pytest 的权限位用例在 Windows 必失败（应加 `skipif win32`）；`socksio` 未安装（SOCKS5 代理不可用）。

### 2.1 明文 HTTP → HTTPS〔B〕

## 7. Binance 实盘 Plan B（详细方案）〔B〕

> 背景：广州服务器无法访问 `fapi.binance.com`（DNS 污染 + SNI 阻断，见 [07 §11.1](07-部署与运维.md#111-服务器访问不到-binance根因已定位)）；Binance 又禁止通过匿名代理访问其服务。所以"面板在国内 + 执行节点在境外"是唯一合规且可落地的结构。

**分工**

| 角色 | 做什么 |
| --- | --- |
| 用户 | 购买东京 Lightsail（历史评估：$5/月，Ubuntu 24.04）；提供 SSH；防火墙只放 22/51820 且仅允许 `81.71.71.131`；创建 Binance 合约**测试网** Key；确认风控上限 |
| 开发 | WireGuard 隧道（`10.66.0.1` / `10.66.0.2`）；东京执行节点（只监听内网 8100，持有 Key，强制风控）；Binance 合约适配器（签名/下单/撤单/对账/手续费/资金费）；面板接入（`provider=binance-node`，默认锁定）；先测试网验证再切真实 |

**服务器选型（历史调研）**

- 首选 AWS Lightsail 东京 `ap-northeast-1`：$5/月（1GB/2TB）；面板也迁则 $10/月 2GB。
- 备选：Vultr / Linode 东京 $5–6、Hetzner 新加坡 €5.49–5.99、腾讯云/阿里云新加坡或东京轻量、Oracle 免费层（不稳定）。
- 参考：<https://aws.amazon.com/lightsail/>、<https://aws.amazon.com/lightsail/pricing/>。

**关键约束**

- 广州服务器可直连 `testnet.binancefuture.com`（历史实测 200、约 1.4 s），所以**测试网可以先用广州面板+测试网**做零成本验证。
- 先测试网、再真实；真实前必须有：订单对账、listenKey 续期、风控熔断、告警。
