## 4. 关键设计决策

### 4.0 Google 登录为什么用 Device Flow（2026-11-18）

- 线上是 HTTP；Google 要求 OAuth redirect URI 为 HTTPS（localhost 除外），无法用标准授权码回调。
- 采用 OAuth 2.0 Device Authorization Grant：浏览器只打开 Google HTTPS 页面输入 code，后端轮询 token。
- 广州服务器访问不到 Google，因此在东京节点加固定端点中继（`scripts/tokyo_google_relay.py`），
  面板经 WireGuard 调 `10.66.0.2:8101`。
- 后台白名单是第二道门：Google 只证明“是谁”，`/admin` 的 `google_users` 决定“谁可以进”。
- 代价：登录多一步输入 code；上 HTTPS 后可再加标准 redirect，Device Flow 保留备用。

### 4.0.1 行情页黑屏（2026-11-18）

- 根因不是“数据量太大”，而是节点 `/api/market/funding` 漏 `summary`，前端访问 `summary.mean_rate` 抛错，
  React 整树卸载 → 黑屏。
- 修复：后端补 summary + 前端兜底 + ErrorBoundary；同时按视觉优先做懒加载（180 根 K 线、
  资金费卡片进入视口才请求、图表延后挂载）。

**用法**：想推翻某条设计前，先看"代价"列——如果代价在当下可以接受，就不要为"更优雅"去改。

| 决策 | 理由 | 代价 / 已知不足 |
| --- | --- | --- |
| 单用户 + 单令牌（**面板侧无用户表**；`/admin` 另有独立 `admin_user` 表） | 单人使用，零运维成本 | 无权限分级；令牌泄露=全权限；两套凭据要分别管 |
| 纯 hash 路由（无 react-router） | 无服务端 rewrite 依赖，静态托管与 APK 都简单 | 无浏览器 history 语义，APK 返回键需原生兜底 |
| 后端默认监听 `127.0.0.1` | 安全默认，公网必须显式改绑 | 部署时要记得改 |
| 任务队列用线程 + SQLite | 不引入 Redis/Celery，单机够用 | 不能横向扩展；单 worker |
| 前端产物由后端托管 | 一个进程一个端口，APK 无需额外配置 | 改前端必须重新 build |
| 行情失败回退数据集 | 保证面板永远能演示 | 会误导"实时性"，必须看 header 的数据源 pill |
| 模拟盘数据源用 Gate | Binance `fapi` 在服务器不可达，Gate 结构一致且可访问 | 依赖 Gate；标的命名与 Binance 不同 |
| 模拟盘/实盘状态用独立 SQLite | 与研究任务库解耦，reset/备份简单 | 多一个文件要备份 |
| 共享保证金动态分配 | 用户明确要求"共享保证金" | 无固定权重/风险平价；单标的可能吃满额度 |
| 实盘下单默认锁定 + 两段式拒绝 | 先分析后交易，防误发单 | 409/403 两种码容易误判（见 §5） |
| 实盘凭据写服务器 `.env` | 与模拟盘配置统一，重启即生效 | 需要写权限；Secret 不在库里管理 |
| APK 构建期注入 server/token | 用户要求 APK 免登录 | 令牌轮换需重打包 |
| `/admin` 与面板令牌完全分离 | 用户要求"独立后台、账号密码预设" | 多一套凭据要管；默认密码风险 |
| 外部接口白名单测试 | 防止随手接非官方接口 | 新增接口必须同步三处，增加摩擦 |
| 服务内存 cgroup 限制 | 与服务器其他业务共存 | 大回测可能被限流/OOM |
