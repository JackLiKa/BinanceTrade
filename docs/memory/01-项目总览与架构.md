# 01 项目总览与架构

## 1. 项目定位

Gridtrade Panel 是面向 `gridtrade` 引擎的单用户量化面板：

- 后端：FastAPI + SQLite（WAL）+ 后台研究任务队列，提供回放、前向滚动、参数扫描与行情/风控/审计接口。
- 前端：一套 React 单页应用，同时服务两种外壳——桌面浏览器（侧边栏）与 Android WebView APK（底部导航 + “更多”抽屉）。
- **硬边界（重点）**：仅研究与模拟盘。实盘入口可见但锁定——没有实盘适配器、没有订单对账、没有 listenKey 续期。任何后续开发都不应绕过这个边界。
- 单用户、单令牌，无多租户、无用户表。

## 2. 技术栈

| 层 | 技术 |
| --- | --- |
| 后端 | Python 3.12、FastAPI、uvicorn、pandas、numpy、pyarrow |
| 存储 | SQLite（WAL），运行期文件在 `var/` |
| 前端 | React 19、TypeScript 5.9、Vite 6、Tailwind 4、lightweight-charts 5、lucide-react |
| 路由 | 纯 hash 路由（`#/overview` 等），无 react-router、无 pushState |
| APK | 单 `MainActivity` + WebView，无 Gradle，手动 aapt2/javac 17/d8/zipalign/apksigner |
| 测试 | pytest（引擎/OMS/风控/模拟/策略/存储），前端 `tsc --noEmit` |

## 4. 页面与两种外壳

10 个 hash 路由：

| 路由 | 内容 |
| --- | --- |
| `#/overview` | 最新回放权益与回撤、前向滚动月度结果、执行模式、数据源、最近任务 |
| `#/market` | 带成交标记的 K 线、资金费率历史、套息汇总 |
| `#/strategy` | 网格参数、校验、价格区间/敞口/止损风险实时预览 |
| `#/backtest` | 回放 / 前向滚动 / 参数扫描、月度归因、订单流、权益与回撤 |
| `#/paper` | 实时模拟盘：Gate 永续行情、网格纸面成交、手续费/资金费、权益与持仓 |
| `#/orders` | 任务选择、订单/成交表、拒单原因、期末挂单 |
| `#/positions` | 模拟持仓、网格状态、分层库存 |
| `#/risk` | 派生限额、回撤保护、紧急停止、拒单计数 |
| `#/quality` | K 线覆盖、缺口、时间戳单调性、交易规则元数据 |
| `#/settings` | 服务器地址、令牌、执行模式、紧急停止、存储路径、审计日志 |

- 桌面（`lg` 及以上）：左侧边栏。
- 移动（`lg` 以下）：底部 5 项“总览/行情/回测/风控/更多”，抽屉中列全部 9 页并提供“退出登录”。
- 路由入口：`web/src/router.ts`（hash 变化驱动），布局：`web/src/components/Layout.tsx`。
- 设备返回键：WebView 有历史则后退；历史尽头弹出原生菜单（重新加载/服务器与令牌/退出登录/退出应用），见 `apk/src/com/gridtrade/panel/MainActivity.java`。

## 5. 后端 API

```

POST /api/runs/walkforward         202
POST /api/runs/sweep               202

GET  /api/runs/{run_id}
GET  /api/runs/{run_id}/artifact   仅 status == succeeded
```

任务提交后立即返回 run id，前端通过轮询 `/api/runs/{id}` 跟踪状态；任务完成后产物写入 SQLite，再由 artifact 接口取出。

## 6. 认证与令牌

- 支持 `Authorization: Bearer <token>`、`X-API-Token`、`gt_token` httpOnly Cookie。
- WebSocket 用 `?token=`（浏览器不能为握手设置请求头）。
- 令牌来源：`GRIDTRADE_TOKEN` 环境变量，否则首次启动生成 `var/token`（0600）。
- 前端把令牌存 `localStorage['gridtrade.token']`；APK 首次启动有原生设置页，保存服务器地址与令牌到 SharedPreferences，并注入 WebView 的 localStorage。
- **重点**：令牌是单因子，等同全权限。不要提交、不要贴到公开 issue；怀疑泄漏就删 `var/token` 重启（会生成新令牌），或设置 `GRIDTRADE_TOKEN`。

| 变量 | 默认 | 作用 |
| --- | --- | --- |

| `GRIDTRADE_VAR` | `var` | SQLite、令牌、产物 |
| `GRIDTRADE_WEB` | `web/dist` | 构建后的 SPA |
| `GRIDTRADE_SYMBOL` | `GOOGLUSDT` | 默认交易对 |
| `GRIDTRADE_AUTORUN` | `1` | 启动时把遗留的排队/运行中任务标记为失败 |

| `GRIDTRADE_CORS_ORIGINS` | localhost:5173 | 开发源白名单 |

## 8. 数据

- 标的：`GOOGLUSDT`（Binance USDⓈ-M 永续，TRADFI 类）。
- 本地数据集：`research/data/`，约 14MB：
  - `GOOGLUSDT_1m.parquet`（约 337,778 根 1 分钟 K 线）
  - `GOOGLUSDT_funding.parquet`（718 次资金费结算）
  - `GOOGLUSDT_meta.json`、`GOOGLUSDT_grid_sweep.csv`
- 覆盖：2026-03-26 至 2026-11-16（约 235 天），>1 分钟缺口 0，覆盖 100%。
- **重点**：数据不随仓库分发；新机器执行 `research/fetch.py` 拉取。服务器当前无法访问 `fapi.binance.com`，所以实时行情接口超时，面板回退到数据集数据源（价格滞后明显）。

## 9. 回测与撮合模型

- 网格：静态锚点或按 N 根 K 线重新锚定；参数含本金、杠杆、间距 bp、层数、止损回撤、费率、滑点。
- 撮合：状态机模型——相邻格各挂一单，必须由 bar 的 high/low 真正触达价格才成交；上涨 bar 只卖、下跌 bar 只买。修正了旧模型“跨边界回补价记低一整格”的虚假收益。
- 资金费：`cash -= pos * price * rate`（正费率时多头付、空头收）。旧脚本用绝对值记成本，已修复。
- 保守/乐观（intrabar）两种口径；仅 1m bar，无法还原盘中路径，保守口径低估成交与风险。
- 产物：replay（权益/回撤/月表/成交/挂单）、walkforward（月度切片汇总）、sweep（组合表与最佳行）。

## 10. 实时模拟盘（paper）

- 目的：用公开实时行情跑一个纸面网格，持续记录收益、持仓、成交、手续费与资金费。
- 数据源：Gate.io USDT 永续公开 REST（`api.gateio.ws`）。服务器所在网络无法访问
  Binance 合约接口（`fapi.binance.com`），但 Gate 与 `data-api.binance.vision` 可达；
  Gate 同时提供标记价、1m K 线、资金费率与 8h 结算时间，满足需求。
- 默认合约 `GOOGL_USDT`（1 张 = 0.01 GOOGL，最小价格变动 0.01，8h 资金费）。
- 引擎：`src/gridtrade/api/paper.py`
  - 后台线程每 `poll_seconds` 拉一次标记价；
  - 网格：锚点 + (层数-1/＋1)×step 挂买卖单，标记价触达即按挂单价成交（maker）；
  - 手续费：maker/taker bp 分别计费；止损平仓用 taker；
  - 资金费：到 `funding_next_apply` 时按 `cash -= position × mark × rate` 结算，
    从 Gate funding 历史取对应费率；
  - 权益 = 现金 + 持仓 ×（mark − 均价）；记录峰值与回撤；回撤超过阈值自动平仓并 halted；
  - 状态、成交、权益采样、资金费写入 `var/paper.db`（SQLite），重启自动恢复。
- API：`GET /api/paper`、`POST /api/paper/start`、`POST /api/paper/stop`、
  `POST /api/paper/reset`（参数见 `.env.example`）。
- 配置：`.env` 中 `GRIDTRADE_PAPER_*`；未启用时页面仍可查看但启动按钮禁用。
- 边界：不接任何交易所私有接口、不下单，仅公开行情。

## 11. 启动与构建入口

```bash
# 后端
.venv/bin/python -m gridtrade.api

# 前端（typecheck + build，产物 web/dist）
cd web && pnpm build

# 测试
.venv/bin/python -m pytest

# APK（需要 ANDROID_HOME、build-tools 36.0.0、android-34、JDK 21）
./apk/build.sh   # 产出 apk/gridtrade.apk
```

后端直接托管 `web/dist`，所以改前端后必须重新 build 才会在浏览器/APK 中生效。
